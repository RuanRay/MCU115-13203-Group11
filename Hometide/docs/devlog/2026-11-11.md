# 2026-11-11 開發日誌

## 2-3：Worker Token 取得與快取、統一錯誤格式、/api/stations（規格 8.3～8.5、8.7；GUIDE 3.4、附錄 E）
- 使用的 AI：Claude Code（模型：Claude Opus 5.5）；是否開隊：否
- 主要提示：Worker 經 tdx.ts 呼叫 TDX（Token 快取、逾時、401 重試），提供台鐵、高鐵車站清單。
- AI 產出：
  - 新增 `worker/src/tdx.ts`：統一錯誤（`ApiError`、錯誤回應）、Token 取得與快取（記憶體＋Cache API，到期前 5 分鐘更新）、`tdxGet`（自動加 `$format=JSON`、逾時 8 秒、401 更新 Token 重送一次、429 回 QUOTA）
  - 新增 `worker/src/cache.ts`（Cache API 包裝，只快取成功回應）、`worker/src/rail.ts`（`/api/stations` 的 TRA／THSR、台→臺、縣市）
  - 修改 `worker/src/index.ts`：只做路由；每個請求記一行 log（路徑、參數、耗時、狀態、錯誤代碼）
  - 新增 `worker/test/`（setup、tdx、stations 測試與 fixtures）、`vitest.config.ts`；`package.json` 加 `npm test`
  - `docs/GUIDE.md` 附錄 E 新增 `E-7 GET /api/stations`
- 依賴（實作者同意）：vitest 4.1.12（鎖定確切版本）。原本同意的 `@cloudflare/vitest-pool-workers` 0.23.0 夾帶的 miniflare、sharp、undici 有 high 等級漏洞，安裝後移除，改用 vitest＋記憶體 Cache API 替身；`npm audit` 0 個漏洞
- 人工修改與理由（實作者決定）：
  - `sortKey` 依 TDX 回傳順序；`updatedAt` 為 Worker 向 TDX 取得資料的時間
  - `operator=BUS` 第 3 週才支援，目前與缺少／不合法的 operator 一樣回 404 `NOT_FOUND`
  - 回應加 `X-Cache: HIT|MISS` 除錯標頭，用來確認 Cache API 在 workers.dev 上是否有效
- AI 自行決定、待實作者確認：
  - 快取鍵只用驗證過的 `operator`，不含其他網址參數：避免有人在網址加任意參數繞過快取、每次都打到 TDX
  - 台鐵 v3 Station 沒有 `LocationCity`（實測 `$select` 回 OData 400），縣市改從 `StationAddress` 開頭解析（郵遞區號後「兩字＋縣／市」）；高鐵 v2 有 `LocationCity`
  - TDX 回 5xx 對應 `NETWORK`；其他 4xx（例如 OData 語法錯誤 400）對應 `UNKNOWN`；Token 端點拒絕對應 `AUTH`
  - Token 存在名為 `tdx` 的 Cache API；同時多個請求遇到 Token 過期會各自換一次（流量小可接受，程式內以 `ponytail:` 註記）
- 驗收：
  - `tsc --noEmit` 通過；`npm test`：24 個測試通過（401 重試一次、重送後仍 401 回 AUTH、Token 重複使用、記憶體清空時從 Cache API 取回、429／404／5xx／400 對應、逾時、非 JSON、未設定金鑰、錯誤訊息不含金鑰與 Token、台→臺、地址取縣市、快取命中、TRA／THSR 分開快取、BUS 回 404、錯誤不快取）
  - 本機 `wrangler dev` 與正式 `https://hometide-api.hometide-api.workers.dev`：TRA 245 站、THSR 12 站，全部有縣市（台鐵共 19 個縣市），站名與縣市沒有殘留「台」；第二次呼叫 `X-Cache: HIT`（確認 Cache API 在 workers.dev 有效）
- 過程中的問題：
  - 用 Claude Code 的 `!` 執行 `wrangler secret put` 沒有互動式輸入，上傳成空值；實作者改在自己的終端機重設
  - 本機 401 其實是舊的 wrangler dev 程序：在 Windows 上 TaskStop 只停掉外層 shell，workerd 仍佔用 8787 埠，請求一直打到帶著舊 `.dev.vars` 的程序；清掉所有殘留程序後正常。之後停止 dev server 要連同 workerd 一起結束
  - 診斷時曾暫時加入只記錄金鑰長度與字元種類的 log（不含值），已全部移除
- 規格問題／待確認：
  - 8.3 寫 `/api/stations` 回傳「縣市」，但 7.1.2 的 `station` 表沒有縣市欄位；App 端（2-4）目前不保存縣市
  - 8.4 的台鐵車站路徑「範例確認」，但回應欄位與高鐵 v2 不同（沒有 `LocationCity`，資料包在 `Stations` 內）
- spec-reviewer 審查：沒有違反規格的項目。依審查意見修正：
  - GUIDE 3.4-4 改為「快取鍵包含所有驗證過的查詢參數，無關參數不納入」，與實作一致
  - `/api/stations` 的參數驗證、快取鍵與 TTL 移到 `rail.ts` 的 `handleStations`，`index.ts` 只做路由（3.4-1）
  - Token 端點回 5xx 改為 `NETWORK`（原本一律 `AUTH`），4xx 才是 `AUTH`
  - 補測試：Token 到期前 5 分鐘內重新換取、403 對應 AUTH、Token 端點 5xx；「錯誤訊息不含金鑰」改成一定會斷言。共 27 個測試通過，重新部署後正式環境 TRA／THSR 200、BUS 404、health 200
  - 審查列出、待實作者確認：Token 最短快取 60 秒；Cache API 命名空間 `tdx`／`api` 與內部網址 `hometide-api.internal`；非 GET 回 404 而非 405；log 記錄原始 query 字串；`cityFromAddress` 假設縣市為「兩字＋縣／市」（台灣現行縣市都符合，245 站實測全部取得）
