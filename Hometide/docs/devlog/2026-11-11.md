- 主要提示：確認 8.4 所有「待查證」路徑與欄位，範例回應存到 `worker/test/fixtures/`。
- 方法（實作者同意）：`tools/tdx_api_test.py` 含明文金鑰，不讀也不執行；TDX 公開 Swagger 頁面為前端程式產生，無法以工具讀取。改在 `wrangler dev --var PROBE:1` 暫時加一個本機查證端點，經現有 `tdx.ts` 呼叫 TDX（金鑰由 wrangler 從 `.dev.vars` 載入），查證完已刪除、未 commit
- AI 產出：`worker/test/fixtures/` 新增 14 個精簡範例回應（台鐵票價／時刻／即時／車種、高鐵票價／時刻、國道路段／即時／壅塞定義、客運路線／站序／班表／預估到站／票價），共約 126 KB，不含 Token

- 過程中的問題：
  - TDX 呼叫上限：連續 4 次後第 5 次回 429，等待約 2 分鐘才恢復，之後每 20 秒一次都正常。推測是每分鐘次數限制（尚未查證官方數字）；Worker 的快取（8.5）因此很重要
  - Git Bash 會把 `/v3/...` 參數轉成 Windows 路徑，需設定 `MSYS_NO_PATHCONV=1`
- 規格問題／待確認（3-2～3-4 處理時再請實作者決定）：
  - **8.7 台鐵票價「依車種代碼對應」**：ODFare 的 `TrainType` 與時刻表 `TrainTypeCode` 是同一套代碼，可直接對應
  - **對號座判斷**：TDX 時刻表沒有「對號／非對號」欄位，需依車種代碼推定（1～5、11 對號；6、7、10 非對號）
  - **TicketType／FareClass／CabinClass 代碼意義**：無法從文件確認。由數值推定台鐵 FareClass 1 為全票（價格最高，其他為半價）、高鐵 CabinClass 1 標準、2 商務、3 自由座；需在 3-2 前確認選哪一筆
  - **車種名稱**：`TrainTypeName.Zh_tw` 含括號說明（例：「自強(推拉式自強號且無自行車車廂)」），App 顯示需要簡稱
  - **高鐵時刻沒有車種**：E-1 的 `typeCode／typeName` 對高鐵要另外決定（例如固定「高鐵」）
  - **客運票價**：8.7 只寫「全票」，但同為全票有多種價格（優惠／原價、三排／四排座），需決定挑哪一個
  - **客運抵達時間**：班表每站都有 `ArrivalTime`，8.7 的「推算抵達」只在缺值時才需要
  - **客運預估到站**：`EstimateTime` 常常沒有值，`/api/live` 對 BUS 需處理「沒有預估」
