## 9. AI 功能規格

### 9.1 技術與設定

- **SDK：** Firebase AI Logic（`com.google.firebase:firebase-ai`），後端 `GenerativeBackend.googleAI()`。
- **模型：** Gemini Flash 系列（實作時依 Firebase 文件選用當時建議的穩定版本，於 `GeminiClient` 以常數集中設定）。
- **安全：** 啟用 Firebase App Check（Play Integrity；開發期使用 Debug Provider）。
- **輸出：** 一律使用結構化輸出（JSON Schema），不解析自由文字。

### 9.2 自然語言查詢：提示詞

```
你是台灣返鄉交通查詢助理（台鐵、高鐵、國道客運）。請把使用者的一句話轉換成查詢條件，只輸出符合 schema 的 JSON。
今天是 {TODAY}（{WEEKDAY}），使用者的預設運具是 {DEFAULT_OPERATOR}。
規則：
1. operator：提到「高鐵」為 THSR；提到「台鐵、火車、自強、莒光、區間」為 TRA；
   提到「客運、國道客運、統聯、國光、和欣、阿羅哈」為 BUS；沒提到填 null。
2. origin、destination：只填車站、轉運站或縣市名稱（不含「站」字），無法判斷填 null。
   「回家、回學校」等無地名的說法填 null，不要猜測。
3. date：換算成 yyyy-MM-dd；「明天、後天、這週五、下週一」依今天日期計算；沒提到填 null。
4. timeFrom、timeTo（HH:mm）：早上 06:00–12:00、中午 11:00–14:00、下午 12:00–18:00、
   傍晚 16:00–19:00、晚上 18:00–23:59；「X 點以後」只填 timeFrom；沒提到填 null。
5. 與交通查詢無關的句子，所有欄位填 null，並把 unrelated 設為 true。
使用者：{INPUT}
```

### 9.3 自然語言查詢：JSON Schema（Kotlin）

```kotlin
val tripSchema = JsonSchema.obj(
    properties = mapOf(
        "operator" to JsonSchema.enumeration(listOf("TRA", "THSR", "BUS")),
        "origin" to JsonSchema.string(),
        "destination" to JsonSchema.string(),
        "date" to JsonSchema.string(),        // yyyy-MM-dd
        "timeFrom" to JsonSchema.string(),    // HH:mm
        "timeTo" to JsonSchema.string(),
        "unrelated" to JsonSchema.boolean()
    ),
    optionalProperties = listOf("operator", "origin", "destination",
                                "date", "timeFrom", "timeTo")
)
val model = Firebase.ai(backend = GenerativeBackend.googleAI())
    .generativeModel(modelName = GEMINI_MODEL)
val result = withTimeout(8_000) { model.generateObject(tripSchema, prompt) }
val json = result.response.text   // 以 Gson 轉成 TripQueryDto 後進行 FR-AI-03 驗證
```

> 註：Schema 與呼叫方式依 Firebase AI Logic 結構化輸出文件撰寫；若當時 SDK 版本的 API 名稱不同（例如 `generationConfig { responseSchema = … }` 搭配 `generateContent`），以官方文件為準，欄位定義不變。

### 9.4 回饋分類與摘要

**提示詞：**

```
請閱讀以下 App 使用者回饋，只輸出符合 schema 的 JSON：
category：SUGGESTION（功能建議）、BUG（錯誤回報）、DATA_ERROR（班次或票價資料有誤）、OTHER。
sentiment：POSITIVE、NEUTRAL、NEGATIVE。
summary：以繁體中文、30 字以內摘要重點，不要包含個人資料。
回饋內容：{CONTENT}
```

**Schema：** `category`（enum 4 項）、`sentiment`（enum 3 項）、`summary`（string）。只傳送回饋文字，不傳送 Email、uid 或使用統計。

### 9.5 驗證、失敗處理與紀錄

1. 模型回傳後以 Gson 解析，失敗 → PARSE_ERROR。
2. `unrelated = true` →「這句話好像不是查詢車班，請換個說法」。
3. 站名經 StationNameNormalizer（台→臺、去「站」、去空白）後查 StationProvider，0 筆 → STATION_NOT_FOUND；多筆 → 以完全相符者為準。
4. 日期超出範圍 → INVALID_DATE，確認卡提示並預設今天。
5. 每次呼叫寫入 `ai_query_log`；`user_edited` 在使用者按「修改」時更新為 1。
