## 1. 專案概述

### 1.1 背景與問題

外地就讀的大學生每逢週末與連假往返學校與家鄉，規劃回家時面臨五個問題：

1. 台鐵、高鐵、國道客運分屬不同 App，比較運具必須切換 App 並重複輸入起訖站。
2. 返鄉路線高度固定，但每次查詢仍要重新選擇起站、迄站與日期。
3. 熱門時段班次多，難以快速看出哪一班還沒開、有沒有誤點、票價多少。
4. 選好班次後容易忘記發車時間而錯過。
5. 開車或搭客運回家的人，出發前不知道國道塞不塞、開車會不會比坐車慢。

### 1.2 產品目標與成功指標

| 目標 | 衡量指標 | 目標值 |
|---|---|---|
| 常用路線查詢更快 | 從開啟 App 到看到常用路線今日班次的點擊次數 | ≤ 1 次點擊 |
| 一句話查詢可用 | AI 解析測試集（第 9.6 節，35 句）四個主要欄位全對比例 | ≥ 85% |
| 查詢回應迅速 | 有網路時從按下查詢到列表出現的時間 | ≤ 3 秒（P90） |
| 離線仍可用 | 斷網時開啟曾查詢過的路線 | 100% 顯示快取並標示離線 |
| 提醒可靠 | 設定提醒後在發車前收到通知（含重開機後） | 測試 10 次全數收到 |
| 回家方式一眼比較 | 「國道」分頁同時看到開車預估時間與台鐵、高鐵、客運最快抵達時間 | 1 個畫面內完成 |
| 金鑰不外洩 | APK 反編譯後找不到 TDX Client Secret | 0 處 |
| 課程要求全覆蓋 | 第 13 章對照表每一項都有可展示的畫面或程式 | 100% |

### 1.3 範圍

**範圍內（本學期必做）：**

- 台鐵、高鐵、國道客運的車站／站牌查詢、指定日期起訖站班次、票價；台鐵即時誤點、國道客運預估到站
- 「國道」分頁：開車路線收藏、國道路段即時路況（預估行車時間、路線圖）、回家方式比較（開車 vs 台鐵、高鐵、國道客運）
- 自建後端（Cloudflare Workers）：保管 TDX 金鑰、統一快取、整理資料後提供給 App
- 訪客查詢；會員註冊、登入、登出
- AI 自然語言查詢與確認卡、AI 回饋分類與摘要
- 常用路線收藏、「下一班」倒數分頁、出發提醒通知（含重開機重排）
- 班次離線快取
- App 使用紀錄（開啟／關閉、每頁停留時間）與個人統計
- 意見回饋與背景上傳
- 淺色／深色模式

**範圍外（不做）：**

- 市區公車、捷運、停車資訊與完整轉乘規劃
- 高公局原始 VD 資料（改用 TDX 已整理的國道路段路況）
- 訂票、付款、座位劃位
- 推播伺服器（FCM）、多語系、平板專用版面
- 管理後台（回饋資料直接在 Firebase Console 檢視）

### 1.4 假設與限制

- 最低支援 Android 8.0（API 26），目標 SDK 依當學期 Android Studio 預設的最新穩定版（預計 API 35）。
- TDX 需申請會員並經管理員審核才能取得 Client Id／Secret；呼叫次數依會員方案有上限，Token 端點每個 IP 每分鐘最多 20 次。金鑰只存在 Worker 的加密環境變數，App 內不放任何 TDX 金鑰。
- Cloudflare Workers 使用免費方案：每天 100,000 次請求、每次執行 CPU 約 10 ms、每次最多 50 個子請求、Cron Trigger 每帳號 5 個；因此資料篩選盡量交給 TDX 的 `$filter`／`$select`，大型資料的整理改由排程離線產生（第 8.6 節）。
- 國道客運在 TDX 的班表可能只有發車時間；抵達時間若以行車時間推算，畫面一律標示「抵達為預估」。
- 高鐵在 TDX 沒有與台鐵相同格式的逐車誤點資料，因此「誤點」標籤僅提供台鐵；高鐵班次狀態只顯示「已開出／即將發車／未發車」。
- Firebase 使用免費的 Spark 方案；Gemini 透過 Firebase AI Logic 呼叫，須注意免費額度。
- 班次與票價以 TDX 為準，App 不保證與現場公告完全一致，畫面上需註明資料來源。
