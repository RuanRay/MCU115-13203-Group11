### 0.1 文件使用方式

- **給老師：** 第 1–6 項為專題概要；本附件第 1–3 章說明範圍與需求，第 13 章對照課程要求。
- **給組員：** 依第 14 章的模組分工，各自閱讀負責模組的功能需求（第 3 章）、畫面規格（第 4 章）、資料（第 7 章）與 API（第 8 章）。
- **給 AI 輔助開發：** 第 15 章提供「如何把本規格交給 AI」的指引與提示詞範本；每次只提供一個模組的相關章節，並要求 AI 遵守第 6 章的套件結構與命名。

### 0.2 名詞定義

| 名詞 | 定義 |
|---|---|
| TDX | 交通部「運輸資料流通服務平臺」，提供台鐵、高鐵、公路客運的車站、時刻、票價與即時資料，以及國道路段即時路況 API |
| Worker | 本專案自建的後端，部署在 Cloudflare Workers；保管 TDX 金鑰、快取資料，App 只呼叫 Worker |
| 開車路線 | 會員收藏的「國道＋方向＋上路交流道＋下路交流道」組合，顯示於「國道」分頁 |
| 國道客運 | TDX 的公路客運（InterCity），例如統聯、國光的跨縣市路線 |
| 運具 | 本 App 支援的三種大眾運輸：台鐵（代碼 TRA）、高鐵（THSR）、國道客運（BUS）；開車則另由「國道」分頁處理 |
| 起訖站（OD） | Origin–Destination，起站與迄站的組合 |
| 訪客 | 未登入的使用者，可查詢班次，但不能收藏、設定提醒或查看個人統計 |
| 會員 | 已用 Email／密碼登入的使用者 |
| 常用路線 | 會員收藏的「運具＋起站＋迄站」組合，顯示於首頁與「我的路線」 |
| 出發提醒 | 會員對特定班次設定、在發車前 N 分鐘觸發的系統通知 |
| AI 確認卡 | AI 解析使用者一句話後，以 Bottom Sheet 呈現的查詢條件確認畫面 |
| 工作階段（Session） | App 從進入前景到進入背景的一段使用時間 |
| 同步 | 把本地標記為未上傳的回饋與使用紀錄上傳到 Firestore |
