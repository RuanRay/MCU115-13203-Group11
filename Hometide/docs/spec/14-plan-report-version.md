### 14.4 協作規則

- Git 分支：`main`（可執行）、`dev`（整合）、`feature/模組-功能`；合併到 dev 前由阮梓睿審查（阮梓睿自己的程式碼由另一位組員審查）。
- 每週日晚上由阮梓睿主持整合，確認 dev 可編譯並跑過 TC 清單中已完成的項目；各組員回報本週進度與卡關處。
- 介面約定：模組間只透過 Repository 的公開函式溝通；Repository 介面先定義、再各自實作，前期可用假資料版本。

### 14.5 風險與對策

| 風險 | 影響 | 對策 |
|---|---|---|
| TDX 金鑰審核延遲 | M3 無法串接 | 第 1 週申請；先用範例 JSON 開發 |
| TDX 欄位與預期不同 | 票價、山海線無法顯示 | 第 3 週前完成欄位確認；取不到時隱藏該欄位而非報錯 |
| Worker 免費額度或 CPU 限制 | 端點逾時或被拒 | 讓 TDX 先篩選；客運索引離線產生；快取 60 秒以上 |
| 國道客運資料不完整 | 抵達時間、票價缺漏 | 標示「抵達為預估」、票價顯示「—」 |
| AI 準確率不足 | 確認卡常需修改 | 調整提示詞；增加站名別名表；確認卡本來就有修改機制 |
| AI 免費額度用完 | 解析失敗 | 限流每分鐘 5 次；失敗時退回手動表單 |
| 提醒在部分品牌手機延遲 | 通知晚到 | 畫面註明可能延遲；測試報告記錄機型差異 |
| 主要開發者工作量集中 | M3、M5 進度落後影響整體 | 第 5 週起由進度較輕的模組負責人協助 M5 的回饋頁與 SyncService；架構與介面約定在第 1 週就定案，避免其他人等待 |
| 進度落後 | 功能不完整 | 優先完成 M 級需求；S 級（拖曳排序、問候語）可延後 |
